# 认知依据与可执行编辑规则

版本：0.4.0；原文核验日期：2026-09-11。机器可读版本：[cognitive_rules.json](../config/cognitive_rules.json)。本版未新增或重新核验研究；关键句误读与逐段推进规则见传播原则，它们是由真实样例反馈触发的编辑工程措施。

这些研究帮助决定“怎样组织解释、配图与检查”，不能证明本项目文章已让真实中文读者愿意点击、读完或理解。下面选用四项原始实验研究与一项元分析；没有开展读者试验，没有模型自评可替代的真人效果指标。研究结论与本项目的工程推断分开记录。

## 规则怎样进入运行

1. **规划阶段读取配置**：宿主读取 `config/cognitive_rules.json`。保存一个核心理解目标、主要误解、入口问题及预计答案、核心概念的前置关系、每图功能、可选类比映射；按成果类型确定理解目标；不固定所有领域都必须回答同一组机制问题。不能只把文献列表粘进提示后跳过这些产物。
2. **生成阶段应用规则**：从研究问题出发，补所需前提，再解释研究行动或论证以及有限结论；具体顺序服从内容与理解。术语在第一次承担解释任务前补足含义。图片邻近相应段落，关键标签就地说明，图像性质与所表达的证据或关系一致。
3. **成稿后分别审查**：事实核对来自证据表；认知审查依据 COG-01—06，逐项记录 `rule_id`、`status`、`location`、`finding`、`action`。允许 `not_applicable`（例如没有类比），不能把“读到了规则”记录成质量通过。
4. **只看成品的解释检查**：隔离任务收到文章、实际图片与通用审查任务，不收到标准答案、证据库或已知缺陷清单。先自行指出缺失前提，再按本篇成果类型说明问题、论证与边界；问题可随内容调整。回答必须引用正文段落/图号；找不到支持时报告“文章未交代”。保留审查输入范围及是否隔离，结论称为“模型文本/图像检查”，不称“普通人测试”。
5. **修复与缺陷测试**：默认最多两轮修改。优先修事实和关键解释，随后处理编辑建议。对“删唯一解释”“删标题答案”“交换图注/反转箭头”等已确认造成缺陷的副本做检查，并加入含义不变的改写作负对照；报告实际检出、漏检与误报，不能给无样本总体准确率。

自动规则/脚本只能核对字段、链接、声明、图片存在、受控异常以及已编码的有限关系。是否真有解释断点、图像误导或类比偷换，还需要宿主的实际语义与图像审查。本文件与配置提供规则合同，不凭文件存在声称宿主已经执行；实际运行状态以各样例的 `checks.json` 和 `run_manifest.json` 为准。

## 工程默认与硬性要求的边界

正文、段落和句子不设字数目标或上下限；统计只描述篇幅，不触发长度告警、通过、失败或删改要求。需要的解释、例子和衔接可以充分展开，删改依据是重复或离题。聚焦少量切口、最多两轮修订、桌面/手机的具体视口和字号，都是可调整的编辑或测试默认值，不是这些研究给出的科学阈值。图片数量与理解问题按本篇信息需求决定。

COG 规则的 `severity` 统一为 `heuristic`，表示研究到本产品的迁移尚未被直接验证。若审查发现核心结论没有证据、关键解释实际缺失或图意与结果相反，按任务书的准确性/完整性要求处理为必须修复的问题；它的阻断理由是具体缺陷，而非“研究证明不能低于某个分数”。

统一 AI 声明、实际图片可解析、来源记录完整和 HTML/Markdown 导出完整性是产品硬性检查，不是认知科学实验结论。没有真人参与不会阻塞第一版交付，但“真实吸引力、中文理解效果和完读率”始终保留为未验证。
